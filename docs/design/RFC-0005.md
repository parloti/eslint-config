# RFC-0005: Package-Owned Architecture Model for `boundaries`

**Status:** Draft

## Objective

Define the package-owned architecture topology enforced by the `boundaries` module.

## Problem

Repositories using this package follow one canonical source layout. Allowing per-repository topology input adds API and validation complexity while weakening consistency guarantees.

## Decision

The package ships a **fixed architecture model** for the boundaries module.

Instead:

- `import-x` provides generic import hygiene
- `boundaries` enforces package-owned layer descriptors and directed dependency rules

## Fixed Topology

`boundaries` always uses:

- `files`: `src/**/*.ts`
- `ignores`: `src/**/*.spec.ts`
- `elements`:
  - `entrypoint`: `src/index.ts`
  - `bootstrap`: `src/bootstrap/**`
  - `presentation`: `src/presentation/**`
  - `infrastructure`: `src/infrastructure/**`
  - `application`: `src/application/**`
  - `domain`: `src/domain/**`
  - `shared`: `src/shared/**`

## Dependency Direction Rules

- `entrypoint -> bootstrap`
- `bootstrap -> presentation | infrastructure | application | domain | shared`
- `presentation -> application | domain | shared`
- `infrastructure -> application | domain | shared`
- `application -> domain | shared`
- `domain -> shared`
- `shared -> shared`

## Example

```ts
import { config } from "@codeperfect/eslint-config";

export default config();
```

## Validation Rules

- `boundaries` does not accept repository-provided topology input.
- Disabling the module remains available through `config({ plugins: { boundaries: false } })`.
- Direction is enforced by layer, not by import depth, so deep imports remain valid when direction is valid.

## Rationale

This approach enforces one canonical architecture contract with simpler runtime behavior.
